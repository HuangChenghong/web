# 阿里云 ECS Docker 部署指南（从零开始）

> 适用：React + Node.js(Express) + MySQL + Redis 全栈项目
> 服务器：阿里云轻量 2核2G，已装 Docker 26.1.3，域名已解析

---

## 一、整体架构（先看懂这张图）

```
                    用户浏览器
                        │
                        ▼  80 端口
              ┌───────────────────┐
              │   nginx 容器      │  ← 大门，对外只开 80
              │   (反向代理)      │
              └──────┬───────┬────┘
          静态文件   │       │  /api/  /uploads/ 转发
          前端build  │       │
                     ▼       ▼
        /usr/share/nginx/html   backend 容器 (Node:3000)
                                        │       │
                                  ┌─────┘       └─────┐
                                  ▼                   ▼
                            mysql 容器           redis 容器
                           (MariaDB:3306)       (Redis:6379)

    所有容器在同一个 docker 网络 app-net 里，互相用服务名访问
    只有 nginx 对外开 80 端口，mysql/redis/backend 不暴露公网（安全）
```

**核心思想**：nginx 是唯一对外的门。前端是打包好的静态文件（HTML/CSS/JS），nginx 直接读；接口请求 `/api/xxx` 和图片 `/uploads/xxx` 转发给后端容器。

## 三、配置文件逐行讲解

### 3.1 docker-compose.yml 讲解

`docker-compose.yml` 是「一键编排多个容器」的配置文件。你只需要 `docker compose up -d` 一条命令，nginx / backend / mysql / redis 四个容器就全起来了。

```yaml
services: # 所有要启动的容器都写在 services 下面
  nginx: # 服务名 nginx（其他容器可用这个名字访问它）
    image: nginx:alpine # 直接用官方镜像，alpine 是精简版（约 10MB）
    container_name: myapp-nginx # 容器名（docker ps 看到的名字）
    ports:
      - '80:80' # 宿主机80端口 → 容器80端口。对外访问就靠这条
    volumes: # 挂载：把宿主机文件/目录映射进容器
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro
      # ↑ 把你的 nginx 配置覆盖容器内的默认配置，:ro 表示只读
      - ./frontend/build:/usr/share/nginx/html:ro
      # ↑ 把前端打包产物映射到 nginx 的网站根目录
    depends_on:
      - backend # 等 backend 启动后再启动 nginx（顺序保证）
    restart: unless-stopped # 容器崩了自动重启，除非你手动 stop
    networks:
      - app-net # 加入 app-net 网络
    deploy:
      resources:
        limits:
          memory: 128M # 限制最多用 128M 内存，2G 机器必须限

  backend:
    build: # 不用现成镜像，而是按 Dockerfile 自己构建
      context: ./backend # 构建上下文 = backend 目录
      dockerfile: Dockerfile
    expose:
      - '3000' # 只在容器网络内开放 3000，不对公网开（区别于 ports）
    environment: # 环境变量，代码里用 process.env.xxx 读取
      - NODE_ENV=production
      - PORT=3000
      - DB_HOST=mysql # ★ 关键：主机名写服务名 mysql，不是 localhost
      - DB_USER=${DB_USER} # ${XXX} 从同目录的 .env 文件读
      - REDIS_URL=redis://:${REDIS_PASSWORD}@redis:6379
      - SESSION_SECRET_SECRET=${SESSION_SECRET}
    depends_on:
      - mysql
      - redis
    volumes:
      - ./backend/uploads:/app/uploads # 上传图片持久化
    healthcheck: # 健康检查，定期探测容器是否存活
      test: ['CMD', 'wget', '--spider', '-q', 'http://localhost:3000/api/blogs/count']

  mysql:
    image: mariadb:10.11 # 用 MariaDB 替代 MySQL，更省内存且兼容
    environment:
      - MARIADB_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD}
      - MARIADB_DATABASE=${DB_NAME} # 启动时自动建这个库
      - MARIADB_USER=${DB_USER} # 自动建这个用户并授权
      - MARIADB_PASSWORD=${DB_PASSWORD}
    volumes:
      - mysql_data:/var/lib/mysql # ★ 数据持久化，删容器数据不丢
    command:
      - --innodb-buffer-pool-size=256M # 限制内存，2G 机器别开太大

  redis:
    image: redis:7-alpine
    command:
      - redis-server
      - --requirepass ${REDIS_PASSWORD} # 设密码
      - --maxmemory 128mb # 限制最大内存

networks:
  app-net: # 自定义网络，四个容器在同一局域网
    driver: bridge

volumes: # 命名卷（由 docker 管理），数据持久化用
  mysql_data:
  redis_data:
```

**关键概念速记**：

- `ports` = 对外开放（公网能访问）；`expose` = 仅容器间可见（安全）
- `image` = 拉现成镜像；`build` = 按 Dockerfile 自己构建
- `${XXX}` = 从 `.env` 文件读变量，密码等敏感信息不放代码里
- 容器之间用**服务名**互相访问（如 `mysql`、`redis`、`backend`），不是 `localhost`

### 3.2 nginx/default.conf 讲解

nginx 配置的核心是 `server` 块（一个网站）和 `location` 块（URL 路由规则）：

```nginx
server {
    listen 80;                              # 监听 80 端口
    server_name your-domain.com _;          # 你的域名，_ 表示兜底匹配所有

    # ① 前端静态文件
    location / {
        root /usr/share/nginx/html;         # 静态文件根目录
        index index.html;
        try_files $uri $uri/ /index.html;
        # ↑ SPA 必备：找不到文件就返回 index.html，交给前端路由处理
        #   没有 this 行，React Router 刷新页面会 404
    }

    # ② 后端 API 反向代理
    location /api/ {
        proxy_pass http://backend:3000;     # 转发给 backend 容器，末尾不带 / 保留完整路径
        #   请求 /api/blogs/count → 后端原样收到 /api/blogs/count
        proxy_set_header Host $host;        # 透传真实域名给后端
        proxy_set_header X-Real-IP $remote_addr;   # 透传真实客户端 IP
    }

    # ③ 上传文件代理（图片）
    location /uploads/ {
        proxy_pass http://backend:3000;     # 转给后端静态服务
        expires 7d;                          # 浏览器缓存 7 天
    }

    # ④ gzip 压缩（让网页加载更快）
    gzip on;
    gzip_types text/css application/javascript application/json;
}
```

**最常踩的坑**：

- `proxy_pass http://backend:3000/;` 末尾带 `/` → 会把 `/api/` 前缀去掉（后端收到 `/blogs/list`）
- `proxy_pass http://backend:3000;` 不带 `/` → 保留原始路径（后端收到 `/api/blogs/list`）
- 你的后端路由是 `app.use('/api/blogs', ...)`，**必须保留 `/api/` 前缀**，所以用不带 `/` 的写法（我已改好）

### 3.3 backend/Dockerfile 讲解

Dockerfile 是「如何把代码打包成镜像」的菜谱：

```dockerfile
FROM node:18-alpine          # 基础镜像：Node 18 + 精简 Linux
RUN apk add --no-cache tzdata wget   # 装时区数据和 wget（健康检查用）
ENV TZ=Asia/Shanghai         # 设置时区为东八区

WORKDIR /app                 # 容器内工作目录
COPY package*.json ./        # 先只复制 package.json（利用缓存层）
RUN npm ci --only=production # 装生产依赖，不装 devDependencies
COPY . .                     # 再复制所有源代码
EXPOSE 3000                  # 声明端口（仅文档作用，实际靠 compose）
CMD ["node", "bin/www"]      # 启动命令
```

**为什么要分两次 COPY**：Docker 是分层缓存的。先 COPY package.json 再 npm install 是一层；如果代码变了但依赖没变，重新构建时这一层会命中缓存，跳过 npm install，构建飞快。

## 四、部署步骤（按顺序执行）

### 步骤一：本地准备前端打包产物

React 项目在服务器上不跑源码，跑的是打包后的静态文件。先在本地打包：

```bash
# 进入前端目录
cd c:\Users\Administrator\Desktop\python\web\frontend

# 装依赖（如果没装过）
npm install

# 打包，产物会生成在 frontend/build 目录
npm run build
```

打包完成后，确认 `web\frontend\build\index.html` 文件存在。

> 注意：docker-compose 里写的是 `./frontend/build:/usr/share/nginx/html`，所以 build 目录必须有。

### 步骤二：导出本地数据库结构

服务器上的 MySQL 是空的，需要把表结构和数据导出来导入。在本地用 Navicat / DBeaver / 命令行导出：

**方式 A：Navicat**

1. 连本地 MySQL，右键 `blog` 库 → 转储 SQL 文件 → 结构和数据
2. 保存为 `init.sql`

**方式 B：命令行**

```bash
mysqldump -u root -p -d blog > init.sql        # 只导结构（推荐，数据手动加）
# 或导结构和数据
mysqldump -u root -p blog > init.sql
```

把这个 `init.sql` 放到 `web/` 目录下（后面要用）。

### 步骤三：确认 nginx 配置（已帮你改好，只需检查）

我已修好 `nginx/default.conf` 的一个致命问题：原来 `proxy_pass http://backend:3000/;` 末尾带了 `/`，会把 `/api/` 前缀去掉，导致后端路由匹配不上（你的后端注册的是 `app.use('/api/blogs', ...)`）。

现已改成 `proxy_pass http://backend:3000;`（无末尾 `/`），保留完整路径转发。

**你只需做一件事**：把 `server_name your-domain.com _;` 里的 `your-domain.com` 改成你的真实域名，例如：

```nginx
server_name blog.mysite.com www.blog.mysite.com _;
```

没域名暂时用 IP 也行（`_` 会兜底匹配）。

### 步骤四：创建 .env 配置文件

在服务器 `web/` 目录下创建 `.env` 文件（与 docker-compose.yml 同级）：

```bash
# 在 web 目录执行
cp .env.example .env
vim .env
```

把所有 `change-me-xxx` 改成强密码，例如：

```env
MYSQL_ROOT_PASSWORD=Ab3kX9mN$pQ2
DB_NAME=blog
DB_USER=myapp_user
DB_PASSWORD=Lp7wRz@kE5mN
REDIS_PASSWORD=Hy6tGv@bC3xQ
SESSION_SECRET=Df8mNb@vQ7pL2xK9
```

> ⚠️ 密码不要用特殊字符 `/` `@`（在连接串里会冲突），建议用字母数字 + `$` `_`

### 步骤五：把项目传到服务器

本地用 Git 推送或用 scp/FTP 上传整个 `web` 目录到服务器。推荐用 Git：

```bash
# 本地：提交代码
cd c:\Users\Administrator\Desktop\python\web
git add .
git commit -m "准备部署"
git push origin master

# 服务器：克隆
ssh root@你的服务器IP
cd /opt
git clone https://gitee.com/regester/web.git
cd web
```

**注意**：`.gitignore` 里排除了 `node_modules` 和 `build`，所以：

- 前端要在服务器上重新打包（服务器需装 Node），或在本地打包后手动传 `build` 目录
- 最简单做法：本地 `npm run build` 后，单独把 `build` 目录传上去

如果服务器没装 Node，本地打包后用 scp 传 build 目录：

```bash
# 本地执行（PowerShell）
scp -r c:\Users\Administrator\Desktop\python\web\frontend\build root@你的IP:/opt/web/frontend/
```

### 步骤六：把数据库 SQL 挂进 MySQL 容器

MariaDB 镜像有个特性：首次启动时会自动执行 `/docker-entrypoint-initdb.d/` 目录下的 `.sql` 文件。把你的 `init.sql` 挂进去就能自动建表。

编辑 `docker-compose.yml` 的 mysql 服务，加一行 volumes：

```yaml
  mysql:
    image: mariadb:10.11
    ...
    volumes:
      - mysql_data:/var/lib/mysql
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql:ro   # ← 加这行
    ...
```

> 注意：只在**第一次启动**（数据卷为空时）才会执行。之后改 SQL 要先删卷：
> `docker compose down -v`（会删数据！谨慎）

### 步骤七：启动所有服务

```bash
cd /opt/web

# 构建后端镜像 + 启动所有容器（首次较慢，要拉镜像和 npm install）
docker compose up -d --build

# 查看启动状态
docker compose ps

# 应该看到 4 个容器都是 Up 状态
```

### 步骤八：验证部署

```bash
# 1. 看后端日志有没有报错
docker compose logs -f backend

# 2. 测试 API（在服务器上）
curl http://localhost/api/blogs/count
# 应该返回 {"code":200,...}

# 3. 浏览器访问
http://你的域名
# 或
http://你的服务器IP
```

如果看到博客首页，部署成功！

## 五、阿里云安全组配置（重要）

服务器默认防火墙会挡住外部访问，要去阿里云控制台开放端口：

1. 登录阿里云控制台 → 轻量应用服务器 → 找到你的实例
2. 点「防火墙」→ 添加规则
3. 至少开放：
   - **TCP 80 端口**（HTTP 必须）
   - TCP 22 端口（SSH，一般默认已开）
   - HTTPS 443（以后配 SSL 再开）

> MySQL(3306)、Redis(6379) **千万不要**对公网开放！它们只在 docker 内部网络通信。

## 六、常用运维命令速查

```bash
cd /opt/web                              # 所有命令都在项目目录执行

docker compose up -d                     # 启动所有服务（后台）
docker compose up -d --build             # 重新构建后端镜像并启动（改了后端代码后用）

docker compose ps                        # 查看容器状态
docker compose logs -f backend           # 实时看后端日志
docker compose logs -f nginx             # 实时看 nginx 日志

docker exec -it myapp-backend sh         # 进后端容器里看文件
docker exec -it myapp-mysql mysql -u root -p   # 进数据库
docker exec -it myapp-redis redis-cli -a 你的redis密码  # 进 redis
```

**更新代码后重新部署**：

```bash
cd /opt/web
git pull                                 # 拉新代码
# 如果前端改了：本地 npm run build 后传 build 目录
# 如果后端改了：
docker compose up -d --build backend
```

## 七、常见问题排查

### Q1：访问域名显示 502 Bad Gateway

后端没起来或起得慢。看日志：

```bash
docker compose logs backend
```

常见原因：数据库连不上、Redis 连不上、环境变量没配对。

### Q2：前端页面白屏

- 检查 `frontend/build/index.html` 是否存在
- F12 看控制台报错，可能是静态资源路径不对

### Q3：图片显示不了（/uploads/xxx 404）

- 确认 nginx 配置里有 `location /uploads/`（我已加）
- 确认后端容器里 `/app/uploads` 目录存在且有文件
- 确认 docker-compose 里 backend 挂了 `./backend/uploads:/app/uploads`

### Q4：刷新页面 404

nginx 的 `location /` 里没写 `try_files $uri $uri/ /index.html;`（已写）

### Q5：登录后立刻掉线

- session 依赖 Redis，Redis 没连上会这样。看后端日志有没有 `[redis] connect fail`
- 检查 `SESSION_SECRET_SECRET` 是否配置

### Q6：内存不够容器被杀

2G 机器比较紧张。看内存占用：

```bash
docker stats
free -h
```

可以临时调小 `innodb-buffer-pool-size`，或加 swap：

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
```
